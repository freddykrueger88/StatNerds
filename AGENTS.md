# AGENTS.md

StatNerds: sport stats platform (Bundesliga). Monorepo: `frontend/` (React/CRA 5, no TS), `backend/` (Express + pg), `db/` (Postgres). Runs as a 3-service Docker Compose stack. Docs (README, PROMPT.md) are in German; source comments are German.

## Run the stack

```bash
cp .env.example .env
docker compose up -d --build
```

- Ports: frontend `3000` (nginx), backend `8000`, Postgres `5432`.
- nginx in `frontend/nginx.conf` proxies `/api/*` → `backend:8000` and **does NOT strip the `/api` prefix** (the backend mounts every route under `/api/*`, e.g. `app.use('/api/games', …)`). Use `proxy_pass http://backend:8000;` (no trailing slash) — replacing it with `proxy_pass http://backend:8000/;` breaks every `/api` route with 404. The frontend always calls relative `/api` (`src/services/api.js`), so it only works behind this nginx proxy.
- `./backend/src` is volume-mounted into the backend container, but the container runs `node src/server.js` (no nodemon). Editing backend files on the host needs `docker compose restart backend`.
- Postgres data persists in `./db/data`; `docker compose down -v` wipes it. Schema is created by `db/init.sql` (mounted as `/docker-entrypoint-initdb.d/`).

## Build gotchas (all verified; do not "fix" these back)

- **Prisma is pinned to v5** (`prisma`/`@prisma/client` `^5.22.0` in `backend/package.json`). Prisma 7 rejects `url = env("DATABASE_URL")` in `backend/prisma/schema.prisma` (P1012). Prisma is build-time only (client codegen); the app queries Postgres via the shared `pg` Pool in `backend/src/db.js`.
- **Do not re-add `prisma migrate deploy`** to `backend/Dockerfile`. There are no Prisma migrations; the schema lives in `db/init.sql`. `migrate deploy` fails with P3005 (schema not empty) and the container crash-loops.
- **`frontend/package.json` keeps `"eslintConfig": { "extends": ["react-app"] }`** plus the pinned `eslint-plugin-*` devDependencies. Removing either makes `npm run build` fail with "Definition for rule 'react-hooks/exhaustive-deps' was not found" (the `// eslint-disable-next-line react-hooks/exhaustive-deps` in `src/hooks/useFetch.js` references a rule the base config omits).
- `docker-compose.yml`: env values must keep a space after the colon (e.g. `FOOTBALL_DATA_KEY: ${...}`). `FOOTBALL_DATA_KEY:${...}` is invalid YAML.

## Tests / verification

- Backend: `npm test` (Jest, in `backend/`). **Known broken out of the box**:
  - `src/__tests__/prediction.test.js` "Lambda 0 für Auswärts" asserts `home_win > 90` but the correct value is 78.
  - Jest coverage threshold (`functions: 50`) fails because routes/adapters are untested (`--coverage` is baked into the `test` script).
  - Clean signal: `npx jest src/__tests__/scorerMap.test.js` passes.
- **Trap:** the tests copy the implementation (Poisson, `buildScorerMap`) instead of importing it — those functions are not exported from `prediction.js`/`games.js`. Editing the real logic won't be caught; export the functions and import them in tests if you touch them.
- Frontend has no test script; `npm run build` runs ESLint as a compile gate (with the `eslintConfig` in `frontend/package.json`).
- Backend lint: `npm run lint` is **broken** — there is no eslint config in the backend, ESLint refuses to run. Don't rely on it.

## Production deployment

- `docker-compose.prod.yml`: Prod-Stack mit Caddy (HTTPS/Let's Encrypt), Resource-Limits, kein Dev-Mount. Env-Variablen über `.env` auf dem Server; `POSTGRES_PASSWORD` und `PUBLIC_URL`/`PUBLIC_HOST` sind **Required**.
- Caddy holt Let's Encrypt-Zertifikate automatisch für den in `PUBLIC_HOST` angegebenen Domain; HTTP → HTTPS Redirect passiert automatisch.
- `Caddyfile`: konfiguriert Caddy (reverse proxy → nginx:80, Security-Headers). `auto_https off` für lokalen Smoke-Test nötig; in Produktion entfernen.
- GitHub Actions Deploy-Workflow: baut Images lokal, kopiert Assets via SCP, ruft `docker compose -f docker-compose.prod.yml up -d --build` auf. Secrets: `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`.

## Architecture notes

- Backend entry `backend/src/server.js`. In-memory TTL cache: `backend/src/cache.js` — all routes must use this single shared instance (no per-route caches), same for the shared `pg` pool in `db.js`.
- Data comes from OpenLigaDB over axios (no key). League whitelist in `backend/src/routes/games.js`: `ALLOWED_LEAGUES = ['bl1', 'bl2', 'fbl1', 'bbl']` (BBL-SHORTCUT `BBBL1`, `odb(league)` mapped in all URLs; OpenLigaDB hat für `bbl` nur Daten bis 2018 → `resolveSeason` sucht 12 Jahre zurück). A separate system, `backend/src/adapters/index.js` (REGISTRY, full league names like `bundesliga`, `premier-league`), is what new leagues plug into.
- Season from `BL_SEASON` env (defaults to current year). **Liga-Saison wird pro Ligue aufgelöst** (`resolveSeason` in `backend/src/routes/games.js`): falls die laufende Saison bei OpenLigaDB noch keine Spieltage hat (z.B. Frauen-Bundesliga `fbl1`, die später startet), fällt sie auf Vorjahr zurück – automatisch verifiziert über `getavailablegroups`. Sei vorsichtig, wenn du Data per Season abfragst: nutze `resolveSeason`, nicht das rohe `SEASON`. **Frontend-Header/Datumsanzeigen dürfen die Saison nicht selbst aus dem Kalenderjahr ableiten** – das Backend liefert die echte Saison pro Liga via `GET /api/meta/seasons` (`{bl1:{year,label,isCurrent}}`); das Frontend liest sie über den Hook `useLeagueSeason(league)` in `src/hooks/useLeagueSeason.js` (Fallback `seasonLabel()` nur solange `loading`; `isCurrent:false` zeigt einen Hinweisbanner).
- **Global league state:** the frontend holds the selected league in `App.js` via `useLocalStorage('sn_league', 'bl1')` and passes `league` down to all pages (`src/leagues.js` has the `LEAGUES` list). When adding a page, read the `league` prop and pass it through `src/services/api.js` — never hardcode `'bl1'`.
- **Personalisierung (alle localStorage, kein Backend):** `useFavorites` (`sn_favorites` = Liste von `teamId`s, ★ pro Karte) · `usePinnedGames` (`sn_pinned_games` = `matchID`s, 📌 pro Karte, angepinnte Spiele werden in `Games.js` `OpenLigaDbGames`/`ApiFootballGames` zuoberst sortiert – Pin-State liegt dafür im Parent und wird als `pinned`/`togglePin`-Props an `GameCard` durchgereicht, sonst eigene Hooks als Fallback) · `useHistory` (`sn_history`, letzte 10 `{type:game|team|player, id, label, ts, league, game?}` via `push()`; View `pages/History.js` mit Navigation in allen Sportarten-Navs, `onNavigate`-Prop kommt von `App.js`; game-Einträge speichern den Match-Snapshot und öffnen `GameDetail` direkt) · `useNotifyConfig` (`sn_notify_config` = `{types:['goals'|'kickoff'|'final'], leagues:[...], onlyFavorites}`; Methoden-Typen in `hooks/useNotifyConfig.js`). **`useNotifications(league, config)`** (Issue #13) pollt die konfigurierten Ligen parallel (`getCurrentGames`), erkennt Tor-/Anpfiff-/Abpfiff-Übergänge über eine per-`matchID`-Snapshot-Tabelle und filtert auf Favoriten, wenn `onlyFavorites` – ohne `config`-Leagues fällt es auf `[league]` zurück; `types:[]` deaktiviert alles (NotificationToggle zeigt dann einen Hinweis-Toast). Settings.js hat den Block „🔔 Benachrichtigungen konfigurieren“. **Dark/Light-Mode (Issue #7):** `sn_mode` in `App.js` via `useLocalStorage` (Default = `prefers-color-scheme`; **`useLocalStorage` hat KEINE Funktions-Initializer** → System-Default vor dem Hook berechnen); Light = `filter: invert(1) hue-rotate(180deg)` nur auf Top-Nav/`.sn-mid`/Mobile-Nav (Root NICHT filtern, sonst liegt `position:fixed` am Root statt am Viewport); `.sn-light img/video/iframe { filter: invert(1) hue-rotate(180deg) }` doppelt-invertiert Logos korrekt; Umschalter ☀️/🌙 im Top-Nav + Block „🌗 Darstellung“ in Settings.js (`mode`/`setMode`-Props).
- **Data source per league:** `leagueSource(id)` in `src/leagues.js` returns `'openligadb'` (bl1/bl2/bbl), `'apifootball'` (e.g. `champions-league`) or `'espn'` (nba/atp/wta). `Games.js` dispatches to `EspnGames` (espn), `OpenLigaDbGames` vs `ApiFootballGames` (API-Football schedule, round picker, requires `API_FOOTBALL_KEY`, shown as 🔑 hint otherwise). Table/Scorers/TeamStats/Teams/Notifications render `LeagueUnavailable` for non-OpenLigaDB leagues instead of erroring; `Table.js`/`Teams.js` branch espn: nba→`NbaStandings`/`NbaTeams`, atp/wta→`TennisRankings` (+`TennisPlayerProfile`). Sport-Selector in `App.js` (`SPORTS` in `leagues.js`, `sportColor()` per sport), Compare-View `src/pages/Compare.js` (#10). The API-Football adapter (`backend/src/adapters/football/*`, registry `backend/src/adapters/index.js`) is the pattern for adding new international leagues — add a league entry in `LEAGUES` + a registry entry.
- **ESPN-Public-API (**`backend/src/routes/espn.js`, mounted unter `/api/espn`, keyless, eigene TTL-Caches):** `/nba/current` (Scoreboard), `/nba/standings` (Konferenzen, letzte abgeschlossene Saison), `/nba/teams` (30 Franchises inkl. Farben), `/:league/current` (atp/wta = Turniere mit Matches/Sätzen), `/:league/rankings` (150 Ränge), `/:league/player/:id`. Zwei Fallen: custom `User-Agent`-Header → leere Antwort bei Standings (kein Header setzen, nur `opts = { timeout: 10000 }`); `BASE_WEB2 = 'https://site.api.espn.com/apis/v2'` (kein doppeltes `/sports`). Profil-API 404 → Player-Profil = Rankings-Eintrag + Scoreboard-Scan.
- **Player/squad features are API-Football-based** (`/api/apifootball/:league/{teams,squad/:teamId,player/:playerId}`). `Teams.js` lists the API-Football league teams (bl1=78, bl2=79 via `leagueId`) with real ids/logos when a key is set, else the static fallback list — clicking a team shows squad, clicking a player shows profile + season stats. **The old TheSportsDB team profile (`/api/teams/:id`) used wrong placeholder ids (e.g. 133613 = Manchester City, not Bayern) and is no longer used in the UI** — do not revive it. `.env` keys are empty placeholders; users set real keys in Settings (localStorage `sn_key_api_football`), which the backend also accepts via `x-api-key` header.
- Backend league-aware endpoints: `/api/games/:league/*`, `/api/teamstats/:league`, `/api/teams?liga=`, `/api/prediction?league=`, `/api/games/:league/h2h`, `/api/games/:league/compare?team1=X&team2=Y` (Issue #10; Stats+Form aus laufender Saison via `loadAllMatchdays`, H2H über letzte 3 Saisons via `loadSeasonMatchdays(league, season)`, Einträge mit `finished`-Flag). Whitelist: `bl1`, `bl2`, `fbl1` (Frauen-Bundesliga, OpenLigaDB-Shortcut `fbl1`; `fbl2` = 2. Frauen-Bundesliga), `bbl` (Basketball-Bundesliga, Shortcut `BBBL1`).
- Historical & Season-Aware-Endpunkte (Issues #21/#33/#37): `GET /api/games/:league/table?season=YYYY` (Tabelle einer beliebigen Saison, sonst resolveSeason), `GET /api/games/:league/seasons` (verfügbare Jahre via getavailablegroups, 6h-Cache; für bbl nur `[2018]`), `GET /api/games/:league/teamwindow?team=NAME` (nächstes + letztes Spiel aus `loadAllMatchdays`, 5-min-Cache), `GET /api/games/:league/teamform?team=NAME` (Formkurve: letzte 10 beendete Pflichtspiele aufsteigend mit `{date, opponent, score, isHome, goalsFor, goalsAgainst, points, result('S'/'U'/'N'), finished}`; 5-min-Cache; Kernlogik als exportierte `buildTeamForm(league, all, team)` in `backend/src/routes/games.js`, getestet in `teamform.test.js` – wichtig: BBL vergibt 1 Punkt/Sieg, Fußball 3/1). Sonst Helfer: `getTableSeason`/`getAvailableSeasons`/`getTeamWindow`/`getTeamForm` in `frontend/src/services/api.js`. `loadSeasonMatchdays(league, season)` liefert alle Spiele EINER (beliebigen) Saison – davon lebt auch der #21-Saisonvergleich. `components/FormChart.js` (Issue #37): responsives SVG (kumulierte Punkte-Linie + Tore-Linie, S/U/N-färbig) in `pages/TeamStats.js` (⭐-Team per Klick → Kurve) und `pages/Compare.js` (Kurve unter beiden Team-Karten).
- **Views im Frontend (Default `dashboard`):** `pages/Dashboard.js` (#33, Startseite, aggregiert Fußball-NBA-Tennis-Favoriten, Navigation über `onNavigate(view, league)`-Prop) · `pages/SeasonCompare.js` (#21, Vereins-Wahl + Saison-Chips + per-Saison-Karten + SVG-Chart Platz/Punkte, Rohfelder der Tabelle: `won/draw/lost`, `matches`, `goals`, `opponentGoals`, `goalDiff`) · `components/GlobalSearch.js` (#31, Navbar-Live-Suche ["/" oder ⌘K fokussieren, Pfeile/Enter, Escape, ARIA listbox/option]; Daten lazy ab 2 Zeichen: Tabellen+Torjäger+aktuelle Spiele der Ligen bl1/bl2/fbl1/bbl; Ergebnis-Klick: League→games, Club→teamstats, Player→scorers, Match→games) · ★-Favoriten sportartenübergreifend: `useSportFavorites(key)` (`sn_fav_nba`, `sn_fav_tennis`) in `NbaTeams.js`/`TennisRankings.js`, gelesen vom Dashboard. Mobile-Bottom-Nav filtert `mobile:false`-Einträge (compare/seasoncmp/search/teamstats/history bleiben im Top-Nav).
- `ADMIN_API_KEY` (in `.env`) gates `DELETE /api/stats/cleanup` via the `x-api-key` header. Optional external API keys (`API_FOOTBALL_KEY`, `THE_SPORTSDB_KEY`, `FOOTBALL_DATA_KEY`) extend data but aren't required; keys can also be set in the frontend Settings (localStorage).

## Repo hygiene

- **`.gitignore`** sperrt `.env`, `node_modules/`, `db/data/`, `frontend/build/` u.a. aus dem Commit.
- `.env.example` ist eine kommentierte Vorlage; `.env` ist nie im Repo (nur lokal oder auf dem Server).
- Frontend conventions (from README, enforced in code): all `fetch()` through `src/services/api.js`, all persistence through the `useLocalStorage` hook, all loading state through `useFetch` (`src/hooks/`).
